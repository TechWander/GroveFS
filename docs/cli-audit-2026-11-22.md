# GroveFS CLI 排查报告与优化方案

日期：2026-11-22（2026-11-23 增补第 3 阶段）  
范围：`grovefs` 全部 53 个帮助页面、14 个顶层命令及其子命令的人类可读输出、错误路径、边界行为与机器可解析输出。  
方法：遍历 `--help` 生成帮助树；在 40/60/80/100/120 列伪终端与管道模式下测量行长；注入非法参数、缺失存储、空值、控制字符和断管；校验 `--json` 输出纯净性；运行完整测试套件。

| 维度 | 排查前 | 当前 |

## 2. 发现的问题与处理

### 2.1 高优先级（已修复）

| # | 问题 | 证据 | 处理 |
|---|---|---|---|
| H1 | 帮助文本完全不按终端宽度换行 | 优化前 `grovefs manager --help` 最长行 2556 字符 | 在 [Cargo.toml](../Cargo.toml#L76) 为 clap 启用 `wrap_help`；80 列 TTY 下最长行 80，管道下最长 100 |
| H2 | 顶层与子命令列表被整段说明淹没 | `apikey -h` 中每个子命令占 6–12 行 | 为顶层与 `view/apikey/web/manager/refs/layout` 全部子命令增加一句话 `about`，长说明保留在 `--help` 详情中（[main.rs](../src/main.rs#L151) 起的命令定义） |
| H3 | 关键命令族缺少使用示例 | 优化前 28 个帮助页无示例；`apikey`、`view`、`gc`、`refs`、`layout` 等均无 | 为全部命令族及高频子命令补充 `after_help` 示例：`apikey create/list/rotate/calls/purge`、`view create/define/alias/rm`、`layout migrate`、`refs rebuild` 等 |
| H4 | `apikey list --scope bogus` 静默返回全部键 | 非法 scope 与“不过滤”不可区分，易误判审计结果 | 增加 [parse_scope_arg](../src/main.rs#L3022)，非法值立即 `exit 2` 并列出 `any/mount/mcp/admin` |
| H5 | `--for`、`--role` 仅在运行期校验，提示不一致 | `--role root` 需等部署返回错误 | 增加 [parse_account_role](../src/main.rs#L3031) 与 [parse_ha_role](../src/main.rs#L3040)，分别约束 `user/admin`、`primary/standby` |

### 2.2 中优先级（已修复）

| # | 问题 | 证据 | 处理 |
|---|---|---|---|
| M1 | `--label` 允许空值和制表符/换行 | `--label '   '` 可创建无标题键，表格标题为空 | 创建前拒绝空标签与控制字符，并提示改用 `--note` |
| M2 | 视图名错误过于简略且文案分散 | `invalid view name 'a/b'`，无法得知规则 | 新增 [view_name_error](../src/layout.rs#L223)，统一说明“单一路径元素、不以 `.` 开头、非保留名”；`create/fork/define/alias/export/import` 与 MCP 共用 |
| M3 | `du --view ''` 提示 `--view ` 并建议“makes one” | 空视图名提示语法错误 | [no_tree](../src/du.rs#L210) 区分空值与未知视图，分别给出 `--view` 必填提示与 `view list` 引导 |
| M4 | 输出层级不统一，大量散文直接 `println!` | 优化前 256 处直接打印 | 统一走 `cli_style`：`heading/section/kv_block/Table/outline/info/success/warn/note/hint`；剩余直接打印仅用于 JSON、统计原文和需要保持原样的命令示例 |
| M5 | API Key 表在 120 列仍挤压关键列 | 时间戳 27 字符导致 110–120 列出现 `last ...`、`2026-11...` | 时间戳统一截到秒（[short_time](../src/main.rs#L3051)）；小于 110 列切换为堆叠键值布局；各列设置收缩优先级 |
| M6 | `| head` 触发 Broken pipe panic | Rust 默认忽略 SIGPIPE，`println!` 遇断管 panic | 在 [main](../src/main.rs#L3657) 恢复 `SIGPIPE` 默认行为 |
| M7 | 导入/授权等零散错误走原始 `eprintln!` | 无颜色、无统一前缀、不换行 | 改为 `ui::warn/note`，保持 `warning:`/`note:` 可 grep 前缀 |

| # | 问题 | 当前状态 | 建议 |

## 3. 帮助命令验证结果

遍历 53 个帮助页面（含三级子命令）：

- 全部 `grovefs <path> --help` 退出码为 0。
- 全部页面包含 `EXAMPLES`、`USAGE EXAMPLES`、`COMMON USAGE`、`Four view kinds` 或 `MCP TOOL SURFACE` 之一，示例覆盖率 53/53。
- 管道输出最大行宽 100；80 列伪终端最大行宽 80；无越界行。
- `grovefs help`、`grovefs help view`、`grovefs view help`、`grovefs view help create`、`grovefs help apikey create` 均可正确路由，退出码 0。
- `-h` 显示一句话命令说明与简版参数；`--help` 显示长说明、完整参数和示例。

代表性变化：

```text
# 优化前：每条子命令的说明是一段 1–3 千字符的散文
  create  Mint a new API key ... <数千字符>

# 当前
Commands:
  create  Mint a key and print <id>:<secret> once.
  list    List keys, filtered; never prints secrets.
  revoke  Revoke a key; past audit rows keep attribution.
  rotate  Replace an active key's secret in place.
```

## 7. 预期效果

1. 用户在任意 ≥80 列终端中看到的帮助不再溢出，命令列表可在数秒内扫描完毕。
2. 每条命令都能在 `--help` 末尾看到可直接复制的示例，`-h` 保持简洁。
3. 参数拼写错误在解析阶段即被拦截，错误信息包含允许值，不再出现“静默忽略过滤器”。
4. 列表、键值、表格、状态消息共享同一视觉语言：标题—事实—明细—下一步，层级稳定。
5. 管道、日志、窄终端和断管场景均不产生异常输出或 panic。

## 8. 后续建议（按收益排序）

1. **参数文档重排**：把高频参数的段内硬换行合并为单行，交给 clap 按终端宽度换行，消除 80 列下的硬断句。
2. **示例宽度策略**：若需要支持 60 列，统一把示例续行压到 56 列；否则在文档中明确“帮助最低保证宽度 80”。
3. **帮助颜色统一**：启动时按 `TERM=dumb` 设置 clap `ColorChoice::Never`，与业务输出保持一致。
4. **中文化准备**：若引入中文帮助，需要为 clap 帮助列宽补充 CJK 宽度处理，避免表格错位。

## 9. 第 3 阶段增补（2026-11-23）

本阶段在既有排版基础上，补齐“按任务组织帮助、统一术语、机器可解析、全命令宽度验证”四项。

### 9.1 帮助结构

- 顶层 `--help` 增加 **COMMANDS BY TASK** 分组：Create & shape / Serve a cluster / Mount & inspect / Access & audit / Maintain，紧跟在产品说明之后、`Usage` 之前。
- `--help` 末尾增加两块稳定契约：
  - **TERMS**：base view / derived view / alias / fork / metadata root / roster / control plane 的统一释义。
  - **OUTPUT CONTRACT**：人类界面、管道、机器输出（`--json`、`du` 的 `SIZE<TAB>PATH`）、退出码（0/1/2）各一条。
- `view --help` 增加 **USAGE EXAMPLES**（建树、发布 lens、alias、fork+graft、远程控制面），随后保留“四种视图由哪个动词创建”的速查表。
- `mcp --help` 在工具清单后增加 **USAGE EXAMPLES**（本地信任、API Key + 客户端配置、PG 控制面）。
- 示例覆盖率由 51/53 提升到 **53/53**；管道最大行宽 100，80 列 TTY 最大行宽 80。

### 9.2 机器可解析输出

## 10. 第 4 阶段增补（2026-11-23）

### 10.1 帮助页参数说明补全

- 新增自动扫描：遍历 53 个帮助页，检测“选项头后无任何说明文字”的条目；修复前共 35 处（`view fork/define/rm/alias/export/import/move/pool`、`apikey create/revoke/rotate/secret/set-ro/update`、`web account create/passwd/role/enable/disable/rm`、`web grant add/rm/list`）。
- 统一写法：一句话说明“这个参数是什么”，必要时补一句“为什么/后果”；`--label`、`--id`、`--account`、`--base`、`--view` 等重复参数使用同一措辞，便于跨命令迁移阅读。
- 复测：53 页中真实选项的空说明为 0；示例覆盖仍为 53/53，最大行宽 100。

### 10.2 帮助页视觉分层

- 通过 clap `Styles` 为帮助页统一一套强调色：区块标题（Usage/Commands/Options/EXAMPLES）使用松绿加粗下划线，命令名与选项使用松绿加粗，占位符使用暗灰，错误使用红色加粗。
- 颜色仅在 TTY 启用；管道/重定向下 clap 自动关闭 ANSI，`OUTPUT CONTRACT` 的“纯文本可 grep”承诺不变。
- 80 列伪终端下逐页复核：无越界行、无换行错乱；所有帮助页退出码 0。

### 10.3 控制台 Web UI

- 信息架构：总览页的“本部署”面板去掉与上方计数卡重复的 namespace/credentials/accounts/activity 四行，改为“后端、配置根、进程角色、审计留痕”四项唯一事实；审计页的密钥归属说明只在按 key 过滤时出现，未过滤页面不再以两段长文收尾。
- 排版与对比度：`--fg-faint` 由 #899187（2.8:1）调整为 #68746b（约 4.2:1），表头、字段标签、微说明在浅纸上达到可读对比度；表头字号 10.5px→11px；标题启用 `text-wrap: balance`，正文 `text-wrap: pretty`。
- 表格：窄屏超宽表增加左右滚动阴影（纯 CSS 双层 cover/shadow，表格放得下时不可见）；`owner/view/mode` 列禁止把“未指定”竖排折成三行。
- 交互：路由切换 180ms 淡入上移，切换后回到新页面顶部（粘性导航可在长表格中途切页）；总览计数卡 20ms 级联入场，且使用 `backwards` 填充以保证 hover 抬升不被动画锁死；新增“跳到正文”跳转链接（不写 `location.hash`，避免与 hash 路由冲突）；`main` 成为可聚焦地标。
- 响应式验证：320/390/480/640/768/1024/1280/1440 八档宽度下，五个页面均无水平溢出；390 宽下表格保留横向滚动并由右缘阴影提示。
- 控制台校验：`npm run typecheck`、`npm run lint`、`npm run i18n:audit`、`npm run build` 全部通过；`cargo check --all-targets`、`cargo test` 全部通过。
