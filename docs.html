GroveFS 使用说明

一种用户视图 FUSE 文件系统:物理数据集中存放在硬盘,不同用户挂载各自看到独立的文件列表,列表支持自定义文件夹层级,彻底脱离 NFS。

语言 Rust FUSE fuser 0.18 多线程 元数据 SQLite(rusqlite bundled) 传输 自定义 TCP 帧(非 NFS/gRPC) 全板 GREEN 14 套件(build+unit+posix+edge+e2e+remote+errors+resilience+concurrent+metasrv+ha+striping+locks+freshness)

1是什么 / 核心概念

一句话:把「谁能看到什么(视图)」和「数据实际存在哪(对象)」彻底分开。每个用户一棵独立目录树,互不可见;字节统一存在物理块目录里。

视图 view

每个用户一棵独立目录树(含自定义层级),存在一个 SQLite 库:<home>/meta/<user>.db。不同用户互不可见。

数据对象 object

文件的真实字节。一个文件 = blocks/ 下一个以 UUID 命名的对象(或条带化的多个分块)。视图目录项指向对象 key。

基目录 --home

同时容纳 blocks/(数据)和 meta/(视图)的物理根。默认 $GROVEFS_HOME 或 ~/.grovefs。

关键:视图与数据天然分离。视图只是「目录树 + 指针」,字节永远在 blocks/。这正是"不同用户挂载显示不同列表、数据都在硬盘上"的实现基础。
--view 与路径容量:--view 是视图命名空间的任意标签,与 Linux 用户名无关——不调 getpwnam、不校验 uid、不要求 useradd。alice、team-a、u42、研究组 都可用,只用作 ① <home>/meta/<user>.db 库文件名 ② FUSE mount 上的 grovefs:<user> 标签。鉴权 = 能访问 --home/blocks/ + 可选 --token,不来自 Linux 用户身份。一个用户一棵树,树内可 mkdir/touch 任意多个文件与目录、任意深度,与自家 home 无差异;跨用户隔离的粒度是「整棵视图树」而不是单个路径。--manifest 只是骨架预建入口,不是路径数量上限。

2架构与原理

三层解耦,全走 trait 抽象:

┌─ FUSE 挂载进程  fs_impl.rs:GroveFS(&self, 多线程安全)
│    ├── MetaProvider trait  视图树访问(12 方法)
│    │     ├── 本地:  MetaEngine  → <home>/meta/<user>.db
│    │     └── 远程:  RemoteMeta  → meta-server(中心权威)
│    └── StorageBackend trait 数据对象 IO
│          ├── 本地:  LocalBackend → <home>/blocks/<key>
│          ├── 远程:  RemoteBackend → data-server
│          └── 条带:  ShardedBackend → 多 data-server
└─ 传输:自定义二进制帧 over TCP(定长头+变长体),连接池并发

为什么这样设计

  • trait 接缝可插拔:本地/远程/条带对上层透明,切换只是换个实现。
  • 中心 MetaServer:同一用户在多客户机共享一份权威视图,不再各存各的副本导致分叉。
  • 事件总线 + Notifier:写成功后向订阅者推送失效,解决"默认缓存下内容新鲜度"。
  • fuser 0.18 多线程:每线程独立 /dev/fuse fd(clone_fd),请求并发派发不串行。

3快速上手(单机本地模式)

数据和视图都在本机同一个 --home,无需任何 server,先体验功能最快。

Y=./target/release/grove
BASE=/data/myfs                       # 物理基目录

# 1) 初始化两个用户的视图
$Y --home $BASE init --view alice
$Y --home $BASE init --view bob

# 2) 挂载(前台运行,Ctrl-C 即卸载;或加 & 后台)
$Y --home $BASE mount --view alice --mountpoint /mnt/alice
$Y --home $BASE mount --view bob   --mountpoint /mnt/bob     # 另一终端

# 3) 像普通目录一样读写、建自定义层级
mkdir -p /mnt/alice/projects/2026
echo "年度报告" > /mnt/alice/projects/2026/报告.txt
ls /mnt/bob                                      # bob 看不到 alice 的文件

# 4) 卸载
$Y umount --mountpoint /mnt/alice
视图隔离:/mnt/alice 与 /mnt/bob 是两棵独立的树,互不可见;层级(mkdir 嵌套目录)完全自定义。

4用 manifest 预建自定义层级

init --manifest 在建视图时一次性铺好目录骨架。每行仅两种指令:mkdir <path> 或 touch <path>,行首 # 为注释。

# seed.txt
mkdir projects
mkdir projects/2026
touch projects/2026/README.txt
$Y --home $BASE init --view alice --manifest ./seed.txt
# 输出:applied seed manifest ./seed.txt

挂载后即见预建层级;重复 mkdir/touch 幂等,不报错。

5生产拓扑:中心存储 + 多客户机 LAN 挂载

真实场景:数据放中心集群,多台客户机经 LAN 挂载,同一用户跨机器看到同一份权威视图。拆成两个服务:

# ===== 中心节点 =====
$Y data-server --listen 0.0.0.0:50100 --root /data/cluster/blocks
$Y --home /data/cluster meta-server --listen 0.0.0.0:50110

# ===== 每台客户机(有本地 --home,但不存权威数据/视图) =====
$Y --home /local/home mount --view alice \
     --data 10.0.0.5:50100 --meta 10.0.0.5:50110 /mnt/alice
选项作用
--data host:port文件 IO 走网络到 data-server,不碰客户机本地盘(非 NFS)。
--meta host:port视图由中心 meta-server 提供 → 多客户机挂同一用户 = 共享同一棵权威树。
--data a,b,c逗号分隔多地址 → 启用跨 server 确定性条带(见 §7.2)。
--meta 主,备故障转移列表,主挂自动切备(见 §8)。

客户机本地不留视图副本,--home 只放临时缓存。

6跨客户端一致性

模式命令行为
实时失效推送(默认,推荐)仅 --meta一客户端写成功后,meta-server 经事件总线向同用户其它订阅者广播失效(inval_entry+inval_inode),对端下次访问即时可见,无需轮询。
--strict 强一致兜底加 --strict关闭内核属性/dentry 缓存并 FOPEN_DIRECT_IO 直读,写立即可见。代价:零客户端缓存,往返更多。
失效须成对推送:inval_entry(目录项)与 inval_inode(inode)要一起发,否则对端可能拿到陈旧属性。
默认即新鲜:非 --strict 的推送失效模型已保证「A 写成功 → B 下次访问即时可见」,无需轮询、无需 --strict(由 .build-bin/test_freshness.sh 端到端证明:顺序追加 100 行 / 截断 / 反向读三类场景均在 <500ms 内对端可见)。--strict 不是保新鲜的唯一通道,只是在 writeback 脏页 flush 与远端失效交错的极端竞争窗口下,选择完全旁路内核缓存的更保守兜底。
分布式 advisory 锁:flock / fcntl F_SETLK/F_GETLK 经 meta-server 的 locks 表(SQLite)集中仲裁,跨进程、跨机生效;主备切换后锁状态随快照复制存活。锁回收两条路径:①持锁进程崩溃——内核关 fd 触发 FUSE release(携带匹配 lock_owner),锁行即时删除,远小于 lease;②mount daemon 整机崩溃——无 release 也无续约,锁在一个短 lease(默认 15s)内过期被扫;存活持有者由 daemon 续约心跳(每 lease/3)持续续期,永不超时。非合作应用(cp/dd)仍不阻塞,与 NFS/SMB advisory 语义一致(由 test_locks.sh 段 4 崩溃即时回收 / 段 4b 续约跨过 lease 证明)。

7如何处理数据(重点)

7.1 物理布局

  • 单对象:blocks/<key>,一文件=一对象文件,扁平存放(不用深层目录,避免 inode/目录项膨胀)。
  • key 命名:写入时生成 UUID 作对象 key,存进视图 data_ref 字段。
  • 条带编码:data_ref = s<N>:<stripe_bytes>:<uuid>,第 i 块 key = {uuid}#{i},落在 servers[i % N]。无 s 前缀 = 旧单对象,天然向后兼容。

7.2 多 data-server 条带(聚合容量/带宽)

$Y --home /local/home mount --view alice \
     --data 10.0.0.5:50100,10.0.0.6:50100 --meta 10.0.0.5:50110 /mnt/alice
  • 文件 ≥ 16 MiB 才分块;小文件自然只落 chunk0(单节点)。
  • 条带读写内部复用分块并行 IO 原语。
  • 单地址 --data host:port 与旧行为完全一致。
诚实:条带的价值是把大文件摊到多节点的聚合容量。单条已饱和链路(loopback/单网卡)上实测无吞吐增益,须真独立链路才能测出收益——无实测数字不声称收益。

7.3 删除 / GC

unlink 后视图解除引用,后端据 key 尽力删全部分块;条带 remove 展开删所有 chunk,幂等(残留块可被 GC 清)。

7.4 备份与迁移

  • 数据对象:blocks/ 就是普通文件目录,可直接 rsync/文件系统快照备份。
  • 视图库:SQLite <home>/meta/<user>.db。勿在有写活动时裸拷 DB 文件;单机先停写或 checkpoint 后再拷,HA 模式由 meta-server 用备份 API 复制(见 §8)。

8高可用:meta-server 主备

# 主:读写,并把快照周期推送给备
$Y --home /data/nodeA meta-server --listen 10.0.0.5:50110 --role primary --peer 10.0.0.6:50111
# 备:只读服务,主心跳丢失后自动提升为 primary
$Y --home /data/nodeB meta-server --listen 10.0.0.6:50111 --role standby --peer 10.0.0.5:50110
# 主(可选 RPO=0):加 --sync-repl,写返回前同步等备落盘 ACK
$Y --home /data/nodeA meta-server --listen 10.0.0.5:50110 --role primary --peer 10.0.0.6:50111 --sync-repl
# 真 fencing(opt-in):加 --witness <逗号分隔的 data-server 仲裁者列表,推荐奇数 N>,多数派授权把双写窗口收敛为有界(fail-safe)
$Y --home /data/nodeA meta-server --listen 10.0.0.5:50110 --role primary --peer 10.0.0.6:50111 --witness 10.0.0.7:50100,10.0.0.8:50100,10.0.0.9:50100
# 客户端故障转移列表:主挂自动切备继续读写
$Y --home /local/home mount --view alice \
     --meta 10.0.0.5:50110,10.0.0.6:50111 --data 10.0.0.5:50100 /mnt/alice
  • 两节点必须用各自独立的 --home(各存一份视图副本,节点间靠快照复制)。
  • primary 每 ~500ms 推快照 + 心跳 epoch;standby 心跳超时后提升并 epoch+1,旧主恢复发现更高 epoch 自动降级。
  • --sync-repl(opt-in,默认关闭):写 op 返回客户端前同步推快照并等备 fsync + 原子 rename 的 ACK,把 RPO 从 ~500ms 降到 0;代价为多一个控制通道 RTT + 一次 VACUUM INTO fsync。备不可达/超时时诚实降级为 async 并打 warn(不谎报 0)。由 test_ha.sh 段 7(RPO=0)/段 8(分区降级)证明。
  • --witness <addr[,addr...]>(opt-in,默认关闭):用主备都能访问的一个或多个共享 data-server 作独立仲裁者集合(逗号分隔,推荐奇数 N;N=1 即退化为单仲裁、行为与旧版完全一致)。权威需严格多数派 quorum_size(N)=N/2+1 个仲裁者同时授予——每个仲裁者都是下述相同的 Fence 租约节点,meta 侧对全列表并发 fan-out 并按多数派判决(witness_quorum)。多数派交叠保证正确:两个多数派集合必交于≥一个仲裁者,该仲裁者只把 token 顶高给第一个 claimer(第二个见 prev==我 只算续约不算顶高),故同值碰撞天然只有一主。每个仲裁者维护单调 fence token(OP_FENCE 的 fetch_max CAS 回传折入前的值 prev):claim 赢当且仅当 prev < 我的 epoch,prev >= 我 则被 fence(对端胜出或同值碰撞)——用 prev 而非折后 max 正是为了在仲裁者恢复时区分同值碰撞、绝不双主。在任 primary 每 tick 向多数派 续一份有界租约(lease,默认 3s)(多数报 prev>我则自降级);每个仲裁者拒绝重叠租约——同一时刻至多一份活租约,故多数活租约本身即独占权威的证明,写请求由本地租约有效性直接放行(不再每写一个仲裁 RTT,仅每续租一次,摊薄到整个窗口),被 fence 的过期主在租约到点后的下一次复证即拒绝;提升方亦非重叠——须待前任租约到期才可抢占(prev>=candidate 同值碰撞/对端更高,或前任租约尚活,则拒绝/延后,旧主可证明地已停)。数据面同遭门控:元数据面复证拦不住内容字节(write() 先落 backend、再 debounced touch meta),故客户端把其实时 epoch 贴到每个写意图数据帧(create/write/truncate/remove/fsync),作为 witness 的 data-server 对 epoch < token 的帧直接回 EROFS,过期主无法绕过元数据面静默写入内容;被封帧会向权威重取 epoch 并自动重试一次(自愈)。更关键的是 data-server 把「epoch 校验 + 落盘」与「仲裁 claim」用读写锁线性化(claim 取独占会等在途写排空),而 witness 与存储同在一节点,故过期写的字节不可能与新主写交叠——内容撕裂写在仲裁节点上被真正闭合(不再是“有界窗口”)。部署前提:该数据面门控只对被 quorum 顶高过 token 的 data-server(即 --witness 列表内的节点)生效,故须把 witness 与客户端实际写入的内容盘同节点部署;若内容盘在 witness 集合之外,它的 token 恒为 0、数据面 gate 不生效,仅剩元数据面 fence 兜底(不会双主,但少了内容层的第二道防线)。部署前提:该数据面门控只对被 quorum 顶高过 token 的 data-server(即 --witness 列表内的节点)生效,故应将 witness 与客户端实际写入的内容盘同节点部署;若内容盘在 witness 集合之外,它的 token 恒为 0、数据面 gate 不生效,仅剩元数据面 fence 兜底(不会双主,但少了内容层的第二道防线)。FAIL-SAFE:配置了 witness 却组不到租约多数派连续 >宽限(3s)时,节点放弃写权限——primary 自降级、standby 拒绝提升(写冻结,宁牺牲可用也不冒双写;瞬时仲裁错误不误伤单写,持续故障才由宽限兼底)。相比单仲裁的可用性提升:宕掉少数仲裁者仍能组多数续租、不冻结写,且少数仲裁者的 .fence_token 盘丢也不会复活过期主(多数仍保单调 token);唯失去多数才 fail-safe 冻结。每个仲裁者各自持久化 token 到 <root>/.fence_token,其重启不清零。由此双写窗口被租约安全余量(WITNESS_LEASE_SLACK=500ms)界定——对端只能在我方租约到点后取 token,而我方提前该余量停止信任本地缓存租约(而非 peer-only 的不封顶)。由 test_ha.sh 段 9(过期 primary 重启被挡成 standby + token 持久化)、段 10(杀单 witness→自降级 & 拒绝盲升→恢复→恰好一主)、段 11(3 仲裁者宕 1 仍续租不冻、宕 2 破多数才 fail-safe)证明。
诚实标注:① 默认 async RPO ≈ 500ms,极端故障下最后 <500ms 的写可能丢失;加 --sync-repl 可把这批写的 RPO 降到 0。② fencing 需要第三仲裁者:严格两节点、不配 --witness 时无法防脑裂(CAP/共识硬边界,peer-only 双写窗口不封顶);配了 --witness 即 fail-safe——仲裁者多数派不可达时冻结写而非盲写/盲升;primary 持一份不重叠的有界租约(仲裁者拒发重叠租约,多数活租约即独占证明),写由本地租约校验放行、每续租一次对全列表 fan-out(摊薄到整窗),并对内容数据帧按 token 门控,把双写窗口收敛到租约安全余量内且保证收敛单主。多数派仲裁的可用性红利:--witness 取逗号分隔的 N 个独立仲裁者(推荐奇数),权威需多数派 N/2+1——宕掉少数仲裁者仍不冻结写(仅失去多数才停写),比单仲裁消除了 witness 这个单点可用性依赖(N=1 则退化为单仲裁旧行为)。代价:每续租一次向仲裁列表 fan-out。

9鉴权 / 只读 / 性能

Token 双面鉴权

中心 server 若裸监听 LAN,任何同网段主机都能按 key 读写对象/打开他人视图。加共享口令(同时覆盖数据面 OP_OPEN 与元数据面 M_OPEN):

$Y data-server     --listen 0.0.0.0:50100 --root /data/cluster/blocks --token s3cr3t
$Y --home ... meta-server --listen 0.0.0.0:50110 --token s3cr3t
$Y --home /local/home mount --view alice --data ... --meta ... --token s3cr3t /mnt/alice

token 不匹配 → 连接时直接 PermissionDenied,不重试。空 token(默认)= LAN-trusted 无鉴权,仅限可信内网。

只读挂载

$Y --home $BASE mount --view alice --mountpoint /mnt/alice_ro --ro

所有写操作返回 EROFS(内核 MS_RDONLY + 文件系统侧守卫双保险)。适合分发/归档视图。

性能旋钮

项说明
--threads N(默认 4)FUSE 并发派发工作线程,每线程独立 /dev/fuse fd(clone_fd,Linux 4.5+)。0=单线程(遗留/AB 对照)。
分块并行 IO客户端读 ≥1MiB 按 1MiB 切片并发;写 ≥4MiB 分片并发(零协议改动)。
--o allow_other额外 fuser 挂载选项透传。
touch 去抖write() 对同 inode 200ms 窗口去抖 touch_mtime,减少元数据面 RPC 与 HA 日志量(setattr-size 不去抖,语义要求即时)。

10运维与验证

$Y umount --mountpoint /mnt/alice     # 卸载
fusermount -u /mnt/alice              # 等价(前台进程 Ctrl-C 即卸载)
ps aux | grep grove                  # 查看在跑的 server / mount

12诚实标注的边界

以下为本项目遵循"工程诚信"原则明确标注的限制,而非隐藏假设:

  • 传输协议:当前为自定义 TCP 帧,非 gRPC。gRPC(tonic/prost)已做 go/no-go 闸门评估,结论 GO(tonic 0.14 免 protoc),但完整集成有意延后——独立可弃的末位项,现协议已正确且被测。
  • HA:RPO ≈ 500ms(async;--sync-repl 可降到 0)。真 fencing 依赖仲裁者:--witness(逗号分隔的 N 个共享 data-server 作 prev-回传 epoch CAS 多数派仲裁,需 N/2+1 授予)已落地并 fail-safe——仲裁者多数派不可达时冻结写而非盲升;primary 持不重叠的有界租约(仲裁者拒发重叠租约,多数活租约即独占证明),写由本地租约校验放行、每续租一次向全列表 fan-out,并对内容数据帧按 token 门控,把双写窗口收敛到租约安全余量内(保证收敛单主),各仲裁者独立持久化 token 防重启复活;宕少数仲裁者仍不冻结写、少数盘丢不复活过期主(N=1 退化为单仲裁旧行为)。仅严格两节点不配 witness 时仍无法防脑裂、窗口不封顶(CAP 硬边界,须部署第三方仲裁)。
  • 条带:单条饱和链路无吞吐增益,价值在多节点聚合容量;真实多机链路须重测后才可声称收益。
  • 验证环境:全部在 127.0.0.1 回环(模拟 LAN)验证,尚未做真实多机与 fio 级基准。
凡未实测数字处,文档不做收益声称;凡有限制处,均在代码注释与本节明示。
